# KASLR 27.2 RC 24B115: дедупликация с 24B119 + карта непроверенных входов (exclaves / MIG 866900 / AGX shmem)

**Кратко:** 24B115 побайтово совпадает с 24B119 во всех кодовых сегментах, поэтому все прежние негативы по KASLR переносятся без повторной проверки. Реальный фронтир — не MIG/syscall (закрыты), а три никогда не аудированных поверхности 27.2: exclaves (mach trap 88 / MIG 866900 / экспорты _exclaves_exsurfaceroot_*_memory_range), AGX/IOGPU shared page и незавершённый из-за краша динамический скан IOSurface. Отчёт фиксирует, что уже закрыто, и даёт конкретный список дополнений к probe.

## Target

- Устройство: iPhone14,7 / D27AP, T8110 (A15), arm64e.
- ОС: iOS 27.2 RC, build **24B115**, Darwin 27.2.0, xnu `13432.42.3~28/RELEASE_ARM64_T8110`.
- Ядро: `02_KERNEL/kc/27.2_24B115_kernelcache` (67 239 936 B), копия в `02_KERNEL/diff_267_272/kernelcache.27.2RC.24B115.iphone14b`.
- Контекст атакующего: обычное sandboxed-приложение без special entitlements.

## Component

XNU: mach traps, MIG-подсистемы, IOKit (IOSurface/IOGPU/AGX), exclaves.

## Primitive

Ищется info-leak указателя ядра (kernel text / slide) — входная точка для всей цепочки. На момент отчёта примитив **не получен**.

## Evidence

### 1. Дедупликация: 24B115 ≡ 24B119 по коду

`02_KERNEL/research_27_2/STATUS.md` (апдейт SMITH, 2026-10-27):

> «The 24B115 kernel differs from 24B119 by 933 bytes — 15 in the Mach-O header, 918 in `__PRELINK_INFO`, **zero in any code segment**. The 24B115 SPTM is byte-identical to 24B119».

Практический вывод: перепроверять на 24B115 то, что уже закрыто на 24B119, бессмысленно — это тот же код. Расхождение только в метаданных.

### 2. Что уже закрыто (не повторять)

Источник: `01_REPORTS/ОТЧЁТ_27.2_KASLR_CORETRUST.md`, §2.1–2.6 + `02_KERNEL/kaslr_probe/main.m`.

| Путь | Вердикт |
|---|---|
| `mach_port_kobject` | `str xzr,[x21]` — kobject всегда 0, утечки нет |
| `mach_port_space_info` | `iis_table_addr` / `itn_object` занулены (`str xzr`, `str wzr`) |
| `thread_info` | только user VA (`dispatch_qaddr` = user-адрес очереди) |
| `task_info` (flavors 0..32) | указателей ядра нет |
| `kinfo_proc` (pid 0 и self) | kernel-указателей нет |
| новые syscall 148/149/214/215/246/247/249/352 | copyout только занулённых/валидированных структур |
| IOSurface bulk attachments (sel 2/6) | статически: `bzero(out,0xc68)` перед заполнением |

### 3. Динамический probe на 24B115 **не дошёл до конца**

Краш-лог `02_KERNEL/kaslr_probe-2026-10-27-114337.ips` (build 24B115):

- `EXC_BAD_ACCESS`, `KERN_INVALID_ADDRESS at 0xffffffffffffffe8`
- поток: `__bzero` ← `IOSurfaceGetBulkAttachments`
- то есть приложение умерло **внутри IOSurface-этапа**

Следствие: вывод «IOSurface не течёт» на устройстве **не подтверждён**, а часть селекторов `IOSurfaceRootUserClient` (таблица 4/7/13/28/30/34/49/51/64/67/73/88/90/94/109/111) могла вообще не выполниться. Это открытая дыра в доказательной базе, а не закрытый путь.

### 4. Новые, никогда не аудированные поверхности 27.2

**a) exclaves** — крупнейшая новая поверхность релиза:

- MIG/Mach: trap **88 `exclaves_ctl`**, impl `0xfffffff00a21347c`, 8 аргументов
  (`operation_and_flags`, `identifier`, `buffer`, `size`, `size2`, `offset`, `status`) —
  `02_KERNEL/mach_27.2.txt`
- Новые экспорты XNU (`02_KERNEL/diff_267_272/REPORT_26.7.2_vs_27.2RC.md`):
  `_exclaves_exsurfaceroot_lookup`, `_exclaves_exsurfaceroot_surface_memory_range`,
  `_exclaves_exsurfaceroot_backing_surface_memory_range`,
  `_exclaves_exsurfaceroot_surface_usecount_update`
- Функция с именем `*_surface_memory_range` по определению возвращает **диапазон памяти** —
  первоочередной кандидат на утечку kernel VA/PA.
- Ни в одном отчёте и ни в одном probe этот путь не разбирался.

**b) Неизвестная MIG-подсистема 866900** (`02_KERNEL/mig_27.2.txt`):

```
SubsystemStart(866900) start=866900 end=866903 max_sz=1072
  0xfffffff00a2af7c8: <unknown> num=866900 argc=04 reply_descr=1 max_reply_msg=52
  0xfffffff00a2af6ac: <unknown> num=866901 argc=02 reply_descr=1 max_reply_msg=52
  0xfffffff00a2af568: <unknown> num=866902 argc=03 reply_descr=0 max_reply_msg=1072
```

Безымянная подсистема, появилась в 27.2 (в 26.7.2 было 17 подсистем / 343 routine, в 27.2 — 18 / 348). Два routine возвращают reply (descr=1). Имя, права и вызывающий userland не установлены.

**c) AGX / IOGPU shared page** — единственный класс, где исторически kernel-указатели лежали в user-mapped странице. В §2.6 прежнего отчёта помечен как «статически не проверено до конца».

## Reproduction

Проверка дедупликации (уже выполнена, воспроизводима по артефактам):

```sh
sha256sum 02_KERNEL/kc/27.2_24B115_kernelcache
# сверка с 24B119: 933 B diff, 0 в кодовых сегментах — см. research_27_2/STATUS.md
```

Сбор probe:

```sh
cd 02_KERNEL/kaslr_probe && make package
# IPA: kaslr_probe.ipa (arm64, ad-hoc ldid)
```

## Reliability

- Дедупликация 24B115↔24B119: высокая (прямое побайтовое сравнение, зафиксировано в STATUS.md).
- Негативы по закрытым путям: средняя-высокая (статика по декомпиляции + один динамический прогон, который **оборвался**).
- Новые поверхности (exclaves, 866900): не проверялись ни разу — статус «неизвестно», а не «чисто».

## Impact

Пока impact нулевой: примитива нет. Но дедупликация экономит целый цикл — повторный прогон MIG/syscall на 24B115 заведомо даст те же негативы.

## Next step

1. **Починить probe** (падает на `IOSurfaceGetBulkAttachments` при невалидном буфере):
   передавать валидный out-буфер и корректный `count`, обернуть каждый селектор в отдельный
   `@try`/проверку `kr`, чтобы один краш не убивал весь скан.
2. **Добавить в probe три непроверенных пути:**
   - `exclaves_ctl` (mach trap 88) — перебрать `operation_and_flags`, смотреть `status` и буферы;
   - MIG 866900/866901/866902 — попытаться достать routine через userland-обёртки;
   - `IOConnectMapMemory` на `AGXAccelerator` / `IOGPUDevice`, скан первой страницы
     shared memory на qword'ы `0xfffffff0_00000000..0xffffffff_ffffffff`.
3. Прогнать на 24B115, зафиксировать каждый вызов отдельной строкой лога (чтобы краш не терял данные).
4. Если exclaves отдаёт диапазон — сверить его с unslid-адресами из kernelcache и вычислить slide.

## Confidence

- **Высокая** в том, что 24B115 = 24B119 по коду и что закрытый корпус закрыт.
- **Средняя** в том, что exclaves — самый перспективный из оставшихся путей (оценка по новизне и по семантике имён экспортов, не по декомпиляции).
- **Низкая** в любой оценке «утечки нет» для exclaves / 866900 / AGX: они не проверялись.
- Что могло бы опровергнуть: если `exclaves_ctl` требует entitlement и недоступен из sandbox-приложения — путь отпадает для данного контекста атакующего.
