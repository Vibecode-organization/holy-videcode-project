## Фаззинг

`ctauditfuzz` установлен, seed `fuzz.cms` = `appstore_template.cms`,
`fuzz.on` создан, launch в 17:34. Через ~20 секунд устройство перестало
отвечать:

```
idevice_id -l  -> UDID виден
ideviceinfo    -> Could not connect to lockdownd: Mux error (-8)
```

Похоже на kernel panic (парсер CoreTrust в kext) или зависший USB-интерфейс.
`last.cms` и `oracle.log` вытащить не удалось. `usbmuxd` видит устройство,
но не может с ним говорить; частный usbmuxd не может забрать интерфейс
(`LIBUSB_ERROR_BUSY`), а `systemctl restart usbmuxd` требует root.

## Что сделать при возврате телефона

1. Принудительный ребут: Volume Up, Volume Down, затем Side до логотипа.
2. При необходимости — `sudo systemctl restart usbmuxd`.
3. Разблокировать телефон, проверить `ideviceinfo`.
4. Удалить/не запускать `app.lake9674.aquila8809.ctauditfuzz`; убрать
   `Documents/fuzz.on` (иначе при запуске снова начнёт фаззить).
5. Вытащить `Documents/last.cms` и `Documents/oracle.log`:
   ```
   pymobiledevice3 apps pull app.lake9674.aquila8809.ctauditfuzz Documents/last.cms /tmp/last.cms
   pymobiledevice3 apps pull app.lake9674.aquila8809.ctauditfuzz Documents/oracle.log /tmp/fuzz_oracle.log
   ```
6. Crash-логи: `pymobiledevice3 crash pull` / `08_CRASH_LOGS`.

Если `last.cms` есть — это вход, который уронил устройство; его надо
минимизировать и смотреть, kernel panic это или userspace crash.

## Второй запуск фаззера (после фикса watchdog)

Первый crash `ctauditfuzz-2026-11-11-173459.ips` — **не баг парсера**:
`0x8BADF00D`, FrontBoard убил app за блокировку main thread >10s
(`fuzz_loop` → `NSData writeToFile` → `rmdir`). `last.cms` того запуска —
просто мутация на момент watchdog, не crash-input.

Фаззер переделан: `fuzz_loop` унесён в background queue, `idleTimerDisabled=YES`.
Установлен заново, запущен в 17:55. Через ~30s устройство снова перестало
отвечать:

```
idevice_id -l  -> UDID виден
ideviceinfo    -> Could not connect to lockdownd: Mux error (-8)
idevicediagnostics restart -> error -8
```

`usbmuxd` устройство видит, но lockdown не отвечает; похоже на panic/hang
(возможно, `SoftwareBreakpoint` в CoreTrust kext) либо на зависший USB.
`last.cms` второго запуска и crash-логи не вытащены.

Дополнительно: `pymobiledevice3 diagnostics restart` был отправлен в 18:15;
после этого телефон пропал с USB (`lsusb` не видит Apple, `idevice_id` пуст).

## Итог второго запуска (после восстановления)

Фаззер **завершил 300 000 итераций** (`fuzz done`, лог `Documents/oracle.log`,
17:59). Ни одного crash/panic не было. `last.cms` — просто последняя мутация,
не crash-input. То есть 300k случайных мутаций App Store CMS парсер выдержал.

Собран вариант на 2 000 000 итераций (`/tmp/ctauditfuzz-signed.ipa`), но
установить не удалось: параллельная сессия на этом же хосте гоняет
`AccelProbe`/`ScalerCtx` и делает `sudo reset usbmuxd`; установка падает с
`Failed to connect to usbmuxd socket`, CoreDevice — `Device is not connected`.
Сейчас телефон снова не виден по USB.

**Важно:** не запускать 2M-фаззер одновременно с kernel-пробами другой сессии —
это перегружает телефон и может уронить его (и их работу). Нужен эксклюзивный
доступ или координация.

## 2M-прогон и проверка `last.cms`

Собран 2M-фаззер с `@autoreleasepool` (фикс накопления памяти), установлен,
seed — `appstore_template.cms`, запущен. За ~12 минут он не дошёл даже до
`fuzz 5000` (лог: `fuzz 0 ok`), телефон был сильно загружен. Для 2M это
непрактично (дни), поэтому прогон остановлен, `fuzz.on` удалён, телефон
освобождён.

Проверка `last.cms` из `def_sd`-зависания через oracle:

```
hang_last [prod]: ret=0x2000a  policy=0
hang_last [test]: ret=0x2000a  policy=0
```

То есть **вход не воспроизводит зависание**. Зависание после ~75k вызовов —
накопительное (память/ресурсы/окружение), а не отдельный parser bug.
Это закрывает гипотезу «нашли вход в CoreTrust»: её нет.

**Важно:** после восстановления сначала удалить фаззер, иначе он снова
повесит телефон:

```
pymobiledevice3 apps uninstall app.lake9674.aquila8809.ctauditfuzz
```

или хотя бы:

```
pymobiledevice3 developer core-device remove-file appDataContainer Documents/fuzz.on \
  --identifier app.lake9674.aquila8809.ctauditfuzz
```
