# Бинарный парсер OSUnserialize (27.2) — проверка границ

Точки: `0xa8d8754` (обёртка, принимает size) → `0xa8d96f4` (диспетчер, size в x1) →
`0xa8d97a0`…`0xa8da46c` (основной цикл, **820 инструкций**).
Дамп: `parse_bin/binparser.txt`, `parse_bin/binparser2.txt`.

## Что установлено

1. **Длина доходит до парсера.** В `0xa8d96f4`: `cmp x1,#4` (минимум), затем
   `mov x23,x1` и передача в `0xa8d97a0`. В основном цикле длина лежит в `[sp+0x78]`
   (`str x1,[sp,#0x78]` на `0xa8d97a4`) и поднимается в `x10` на `0xa8d9830`.

2. **Граница проверяется перед чтением.** Каждый разбор объекта идёт парой:
   ```
   0xa8d9838  add x26, x28, #4        ; offset следующего объекта
   0xa8d983c  cmp x26, x10            ; x10 = size
   0xa8d9840  b.hi 0xa8da31c          ; выход с ошибкой
   ```
   Так же на строковом пути (`0xa8d9c48..0xa8d9c50`) и на пути массива
   (`0xa8d9c94..0xa8d9ca4`).

3. **Строка**: `0xa8d9c48 add x26,x26,w28,uxtw #2` → `cmp x26,x10` → `b.hi`,
   затем `sub w8,w23,#1` / `ldrb w8,[x27,w8,uxtw]` — проверка завершающего NUL
   **внутри** уже проверенного диапазона.

4. **Рост массива** (`0xa8d9cd4`): `lsl w2,w26,#3` (count·8), `add w3,w2,#0x200`,
   аллокация `0xa2217b4`, затем сверка `cmp w8,w26` / `b.hs` перед записью
   `str x21,[x0,w8,uxtw #3]` в `0xa8d9d30`. Индекс ограничен счётчиком.

5. **Индексированных чтений без предшествующей проверки в дампе не найдено**:
   всего 6 индексированных обращений на 820 инструкций, и каждому в пределах
   ±0x40 инструкций предшествует `cmp` с длиной или со счётчиком.

## Чего это не доказывает

- Проверены пути, которые видны в линейном дампе (объект, строка, массив, словарь);
  ветки, достижимые только через `blr`/косвенные вызовы, не разобраны.
- Утверждение «все 820 инструкций безопасны» не заявляется: цель была проверить,
  отбрасывается ли `size` — **не отбрасывается**, границы есть.

## Вывод

Гипотеза «бинарный парсер читает по offset из файла без сверки с длиной» **не
подтвердилась**. `OSUnserializeXML(buf,len,...)` доносит длину до цикла разбора и
сверяет с ней каждое смещение. Дальнейший поиск OOB надо вести не здесь, а в
потребителях разобранного объекта (применение свойств к IOSurface: `0x9c3ab8c` →
`[dict vtable+0x138]`), где значения из словаря превращаются в размеры и индексы.
