# iOS ≤27.1 内核任意读写（kread/kwrite）利用手册

> 目标机型：iPhone14,7（T8110 / A15），iOS ≤ 27.1（含 27.0.x、26.x）。
> **27.2 RC（24B115）已修复本文全部漏洞**，因此本手册仅在回退到旧版本时有效。
> 目的：从沙箱 App 出发，拿到任意内核读/写。

---

## 0. 前提与边界

| 项 | 状态 |
|---|---|
| MIE（内存完整性） | A15 **没有**，仅 A19/M5 才有 → 数据型攻击不受限 |
| PAC | 有，但数据型攻击（改长度/指针字段）不需要绕过 |
| SPTM | 有，只保护页表；改内核数据对象不受影响 |
| 签名 | 免费 Apple ID 即可；只需一个普通沙箱 App |
| 已知限制 | 无内核调试、无 kdump；崩溃即重启，需持久化 last-config 日志 |

利用范式固定为三步：**信息泄露（KASLR）→ 写原语 → 把写变成任意读写**。

## 2. 信息泄露（拿 KASLR slide）

### 2.1 首选：NECP / CFIL DATA-TRACE（CVE-2026-112665）

27.2 之前，`socket` 策略调试日志（`DATA-TRACE`）会把内核对象指针原样打进日志；
27.2 加了指针净化（`0xa4ecdf8`、`0xa396010`）。

步骤：
1. `socket(AF_INET, SOCK_STREAM, 0)`，绑定到任意本地端口；
2. 通过 `setsockopt(..., NECP_...)` 打开策略 trace（或使用 CFIL 的 trace 开关）；
3. 触发一次包处理，让日志打印 `so`/`inp`/`pcb` 指针；
4. 用 `syslog`/`os_log` 读取（沙箱内 `os_log` 可读自己的，系统日志需 entitlement；备选把 trace 输出到 `netstat` 可见的计数器）。

拿到一个内核指针后：`slide = leaked - 静态地址`（静态地址来自 kernelcache，见 §5）。

### 2.2 备选泄露

- IOHIDFamily OOB read（112515）→ 直接读相邻内核内存；
- IOStorageFamily（112554）→ 越界读到内核指针；
- Compression（113910）→ 未初始化内核内存返回用户态。

## 3. 写原语：`rt_setgate`（CVE-2026-112507）

`PF_ROUTE` 的 `RTM_ADD` 消息里，`sockaddr_dl` 的 `sdl_alen` 没有对网关地址长度做校验，
导致 `rt_setgate` 把超长链路地址拷进固定大小的 `rt_gateway` → 堆越界写，内容与长度可控。

步骤：
1. `s = socket(PF_ROUTE, SOCK_RAW, 0)`；
2. 构造 `rt_msghdr` + `sockaddr_dl`，令 `sdl_len`/`sdl_alen` 大于目标结构容量；
3. `send(s, buf, len, 0)`；
4. 目标路由项需要先存在（`RTM_ADD` 同一 `RTA_DST`），或用 `RTM_CHANGE` 命中已有项。

写什么：
- 相邻 `kalloc` 对象（同 zone）的字段；
- 可控字节写入，重复触发可写多个块。

## 4. 从写原语到任意读写

### 方案 A：socket/pipe 结构（最稳）

1. 堆喷 `struct pipe`（`pipe()` × N）或 `struct socket`，让它们排在受害对象后；
2. 用 OOB 写改相邻 `pipe_buffer->page`/`offset`/`len`，或 `socket->so_pcb`；
3. 通过 `read`/`write` 得到任意物理页读写；
4. 把 `kread/kwrite` 封装为：给定内核虚地址 → 找 `pv` 映射或走 ` physmap` 偏移。

### 方案 B：IOSurface 对象（最短路径）

1. 用 `IOSurfaceCreate` 造大量 surface，堆喷 `IOSurface` 对象（0x3e0）；
2. OOB 写改某个 surface 的 `base`/`allocSize`/`planeCount`；
3. 调用 `IOSurfaceGetBaseAddress` → 用户态直接映射到任意内核内存；
4. 得到 `kread/kwrite`（甚至不需要额外的读写原语）。

### 方案 C：task/proc（需要先有 KASLR）

1. 泄露 `current_task`（通过 §2）；
2. OOB 写改 `task->cred` 或 `proc->p_ucred` → root；
3. 或改 `task->itk_space` 相关字段做端口提权。

## 5. 地址与符号来源

- kernelcache 解开：`ipsw kernel dec`；
- 27.2 的静态地址（未滑动）已在 `kc/27.2_24B115_kernelcache` 里；
- 旧版本（26.x/27.0）用同一条命令解对应 IPSW 的 kernelcache；
- 泄露一个指针 → `slide = leak - 静态地址`；
- 常用目标：`current_task`、`kernproc`、`vm_map`、`kalloc zones`。

## 6. 为什么 27.2 上全部失效

| 漏洞 | 27.2 的修复 |
|---|---|
| 112507 | `rt_setgate` 增加 `sdl_alen` 校验（`0xa49c4e0`） |
| 112476 | `rtsock_msg_buffer`/`nd6_lookup_ipv6` 加边界（`0xa497e90`） |
| 112576 | `vm_fault_copy` 对忙页重试 + 可执行页 retype（`0xa2cf230`） |
| 112665 | NECP/CFIL trace 指针净化（`0xa4ecdf8`） |
| 84495/112474 | `igi_remref`/`mli_remref` drain `inm_dthead` |
| 65350/112679 | `ptmx_kqops_detach` 改为 lookup tty |
| 112517 | `mach_exception_raise` 持有端口引用 |
| 112477 | IOSurface `+0xf1` 死亡标志，在 `root+0x150` 锁内设置 |
| 112696/84494 | ANE chaining 计数 clamp 到 32、endpoint 边界检查 |

27.2 里这些函数都改在正确位置，未发现漏网的 sibling 分支。

---

## 7. 操作注意

- 每次崩溃重启后，`/var/mobile/Containers/Data/Application/<UUID>/tmp/` 下的 last-config 仍在；
- 先做泄露，确认 slide，再做写；不要在同一次运行里既泄又写；
- 写原语触发后立刻检查 `kernel panic` 的 fault address，判断写到哪；
- 回退版本前确认该版本仍可签名安装（Apple 通常只签当前版本）。
