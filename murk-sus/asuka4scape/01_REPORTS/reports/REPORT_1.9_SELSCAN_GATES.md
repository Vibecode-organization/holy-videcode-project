# REPORT 1.9 — SELSCAN/GATES + закрытие memory-pool лида (27.2, 24B115)

Статик-сессия 30.10.2026. Цель — произвольный kernel R/W на 27.2 RC (iPhone14,7,
T8110). Компаньоны: `CONSUMERS.md`, `F1_ANALYSIS.md`, `COW_SIBLING.md`,
`DISPATCHER_RE.md`. Артефакт: `probe/out/KRWProbe.ipa` 1.9 (build 19).

## 0. Вердикт сессии

**Kernel R/W не получен.** Закрыты статикой три оставшихся «дешёвых» лида.
Живых поверхностей в IOSurface.kext больше нет; вся ставка на device-прогон
1.9 (SELSCAN + GATES) и на новые кексты (AGX command buffers / AVE2 / DART /
apfs) после открытия гейтов.

## 1. Лид «memory pool» — закрыт: утечки нет

Цепочка: sel 48 (`0x9c39e0c`) → `FUN_9c3eb68` → сериализаторы `FUN_9c45114`
(Out-Of-Use) / `FUN_9c429e4` (InUse) → `FUN_9c42d48` (на дескриптор) кладут в
словарь `"Descriptor address"` — 64-битное значение из глобального хелпера
`0xa2df760`.

Дизассемблер ядра: `0xa2df760` — обёртка `vm_kernel_unslide_or_perm`. Для
адреса в kernel-окнах (глобальные пары @ `0x7c6a358/0x360`, `0x7c6a378`,
`0x7c6a3a0`) хвост `0xa396010` выполняет `sub x0, x0, [slide]` (глобальные
слайда @ `0x7c6a388`, `0x7c6a570`, `0x7c6a3b0`), для чужих адресов — `x0 = 0`.
Наружу выходит **статический (unslid) адрес или 0** — слайд не светит.

Проверено против 27.0: пер-дескрипторный сериализатор в 27.0
(`0x9c06df4`) имеет тот же вызов-обёртку (thunk `0x9c0decc`). То есть
unslide стоял уже в 27.0 — это не фикс CVE-2026-112665 в этой точке, а
штатная семантика. Идея «в 27.0 сырой указатель» не подтвердилась:
`cmp`/`b.hs`-пары в обоих бинарях смещают отвод веток на 0x2c при том же
каркасе — **код-канал идентичен в обеих версиях, обе чистые.**

Дополнительно:
- sel 47 (`0x9c39cf4` → `FUN_9c3e86c`) = «флаш пула»: требует Mach-порт,
  объект которого — класс пула (`FUN_9c4078c`), и владение текущей задачей.
- sel 49 (`0x9c39eb8`): 1 скаляр (порт), только OOL-вход → та же валидация
  через `FUN_9c40588`.
- Дикшнари сериализации — только размеры/ID/дескриптор-адреса; raw-указателей
  нет (`"Bucket buffer size"`, `"Pool Id"`, `"Length"`, `"Options"`).

Остаточный вопрос (только device): как получить порт пула. Класс-гейт стоит в
`FUN_9c4078c` (метакласс @ `0x806a720`); SELSCAN 1.9 запишет точный kr для
sel 45-49 с обычными портами приложения.

## 2. Карта селекторов 13-59 (все прочитаны, дизассемблер из кекста)

Группы:

| селекторы | что делают | триаж |
|---|---|---|
| 13 | create-from-memory-2, 1 скаляр | конструктор, `memset(0)`, без выходов |
| 14-16, 20-25 | «trap»-ветки, 1-4 скаляра, ск. выход 1 | читают скаляры, читают/пишут флаг клиента — без структур |
| 17/18 | lock/unlock (0x18-in) | ветка scalarInput[2] в `FUN_9c3d408`; фикс CVE-2026-112477 |
| 19 | set port name | in ≥ 0x200, NUL на конце, копия в client+0x…0x200, "%.512s" |
| 24 | plist-движок (0xc + XML, ≥0x11) | `FUN_9c3d560`; OOL-вход = raw-байты движка |
| 26 | plist-движок + var-out | тот же класс `FUN_9c3f77c`, что и sel 10; ≥0xd-in |
| 27 | **0xa0-вход = сырые create-props (путь IOSurface.framework)** | `b 0x9c3d7c8` |
| 28 | get 0xa0 (props наружу) | `b 0x9c3d838` |
| 29-33, 35-39 | attach-обёртки, фиксированные скаляры | шлют скаляры в сеттеры |
| 34 | info 0xc68 (memset(0) в `0x9c2c18c`) | чисто |
| 40 | async-флаг, 0-0 | пусто |
| 41-44 | fence-обёртки (4 скаляра) | шлют скаляры |
| 45-46 | движок + var | `FUN_9c3e384` (как sel 27-путь) |
| 47/48 | пул (см. §1) | class-gate |
| 49-51 | OOL-пути | 49: 1 скаляр; 50: 2 скаляра + OOL-in; 51: 2 скаляра + OOL-out |
| 52/53 | движок `FUN_9c3c7fc` (общий с sel 54) | 0x28-in / var-in |
| 54 | движок `FUN_9c3c8d4` | 1 скаляр + 1 ск.-выход |
| 55-58 | attach/scalar-обёртки | читатели фиксированных полей |

Выводы:
1. **Ни один из 59 селекторов не пропускает сырую длину** в память: каждый var-вход
   проходит класс-валидацию движка (≥ 0xd/0x11/0xc-заголовок, plist/NUL), а
   обработчики скалярных наборов идут в сеттеры объектов, где длины
   определяются типом, а не числом.
2. **Все outs либо `memset(0)`-инициализированы** (`0x9c2c18c` для 0xc68),
   либо копируются из serialized OSObject'ов, размер которых задаёт ядро
   (длина сериализации), либо MIG-инициализированы пользователем.
   **Ни одного copyout неинициализированного kernel-буфера** — «KASLR-хвост»
   из §4.4 отчёта ФИНАЛ по IOSurface закрыт.
3. Единая точка разбора пользовательских структур — тот же property-движок,
   что уже проаудирован (VALIDATOR_AUDIT/CONSUMERS). Новых потребителей
   compressed-геометрии нет.

## 3. Новая карта путей (для будущих сессий)

- `0x9c3d7c8` / `0x9c3d838` — конвертация 0xa0-структуры в props-словарь
  (27 и 28 селектор) — это путь, которым IOSurface.framework вызывает
  `IOSurfaceCreate` из приложения; проверять при новых полях 0xa0-структуры.
- `0x9c3f77c` — общий движок var-запросов (sel 10/26); всё, что попадает
  сюда, уже покрыто VALIDATOR_AUDIT.
- `0x9c3d560` — движок sel 24 (без выходов); read-only полезность —
  триггеринг парсера без ответного буфера.

## 4. KRWProbe 1.9 (build 19) — что добавлено

- **SELSCAN**: все 60 селекторов с точным ABI из таблицы `sMethods`
  (не как 1.2 SCAN SEL, который звал всё с 1/8 скаляров и получал
  0xe00002c2). var-in = 0x100 байт (sel 13 = 0x210 с именем в хвосте),
  var-out = 0x800, весь ответ префиллится 0xA5, после вызова сравнивается
  хвост: что осталось 0xA5 — пользовательское, что изменилось — ядерное.
  Сканирование ответа на kernel-указатели (то же правило, что в LEAK:
  `[0xfffffff007004000, 0xfffffff00aa78000)` = TEXT, иначе K-range).
  Вывод: `<run>/selscan.txt`.
- **GATES**: IOServiceOpen типы 0-8 для `AGXAcceleratorG14P`,
  `AppleAVE2Driver`, `AppleH11ANEInterface`, `AppleM2ScalerCSCDriver`,
  `AppleJPEGDriver`, `IOGPUFamily` — разделить «сэндбокс сказал нет»
  (0xe00002e2), «тип клиента не тот» (0xe00002c7) и «драйвер не смог»
  (0xe00002bd). Если какой-то тип открывается — immediately sel0-probe.
- Всё остальное (SAFE/CREATE/SCAN/HARD/LEAK/F1/MUTATE) — без изменений от 1.7/1.8.

IPA: `probe/out/KRWProbe.ipa`, 115 561 B, sha256 `03e9aecf…17d8`. Версия в
бинаре: 1.9 / 19.

## 5. Что нажимать на устройстве 27.2 RC

1. **SELSCAN** → смотреть `selscan.txt`: любые `ptrs>0`, любые не-`0xe00002c2`
   ошибки у 13-59, и особенно что вернут 45-49 (валидация пула).
2. **GATES** → если какой-то тип AGX/AVE2/ANE/Scaler/JPEG/IOGPU открывается
   (не 0xe00002e2), — это новая поверхность; сообщить kr-таблицу.
3. Существующие F1/HARD/LEAK — по мере надобности, но по статику они уже
   исчерпаны: F1-метадата не имеет потребителя в ядре, LEAK sel10 чист.

## 6. Честная граница

- Всё выше — статика по бинарям (`kexts/iosurface/27.2`, `kcore/272`);
  устройство не проверялось в этой сессии.
- Класс-гейт пула не разрешён до имени класса (декодер chained-указателя
  выдаёт не тот формат для `__DATA_CONST` 27.2 — нужно добавить mask 0xffffffff);
  на device-вердикт не влияет.
- SELSCAN var-in посылает только «формально корректные» обёртки; целевые
  фаззеры (MUTATE/HARD) остались теми же.
