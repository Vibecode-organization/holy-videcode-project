# iOS 27.2 (24B115) — AGX / JPEG user client: итог разведки

**Устройство:** iPhone14,7, iOS 27.2, build 24B115, UDID REDACTED-UDID
**Kernelcache:** `kc/27.2_24B115_kernelcache` (fileset, chained fixups, arm64e)
**База для декода указателей:** `0xfffffff007004000 + (raw & 0xffffffff)` для auth-rebase
**Прогоны:** KRWProbe 2.1 … 3.11 (21 лог)
**Дата:** 2026-11-02

---

## 1. Вердикт

| Звено цепочки | Статус |
|---|---|
| Достижимая kernel-поверхность | **есть** — AGX type 1, AppleJPEGDriver types 0..8, AppleM2ScalerCSCDriver types 0..8 |
| Создание kernel-объектов | **есть** — GPU-ресурс, IOCommandQueue, IO command buffer |
| Утечка адреса (KASLR) | **нет** — 0 находок |
| Повреждение памяти (OOB/UAF/type confusion) | **нет** |
| Произвольное чтение/запись | **нет** |

Эксплуатационных звеньев получено **0 из 3**. Всё, что найдено, — легальные
вызовы API; ни один из них не даёт записи за пределы своих объектов.

## 2. AGXAcceleratorG14P, client type 1

### 2.1 Открытие

```
type 0     -> 0xe00002c7  (kIOReturnUnsupported)
type 1     -> 0x0         OPEN
type 2..8  -> 0xe00002c7
```

`AGXDeviceUserClient`, vtable `0xfffffff007c94190`, 199 методов, наследует
`IOGPUDeviceUserClient`. Собственных dispatch-таблиц у класса нет — он
использует таблицу IOGPU.

### 2.2 Настоящая таблица диспетчера 27.2

```
TABLE C @ 0xfffffff007fea200, 55 записей по 0x18
```

Полный дамп снят и совпал с наблюдаемым поведением. Отличия от таблицы 23F84 —
переменные размеры:

| sel | si | szi | so | szo |
|---|---|---|---|---|
| 6 | 0 | 0xffffffff | 0 | 0x10 |
| 8 | 0 | 0xffffffff | 0 | 0xffffffff |
| 22 | 0 | 0 | 0 | 0xffffffff |
| 25 | 4 | 0xffffffff | 1 | 0 |
| 45 | 1 | 0xffffffff | 0 | 0 |
| 52 | 2 | 0xffffffff | 0 | 0 |
| 53 | 2 | 0xffffffff | 0 | 0 |

### 2.3 Что работает

```
sel 0,1,2,3,4,5   — device info / config (0x40, 0x40, 0x218, 8, 0x20, 0x10)
sel 16,17,19,21,23,28,41,42 — очереди/события/запросы
sel 8             — new_resource, УСПЕХ с реальным IOSurface
```

`sel2` возвращает 0x218 байт конфига; первый qword — user VA 16-КБ страницы
(`prot=0x1`), содержимое — GPU-конфиг (16-битные пары), kernel-указателей нет.

### 2.4 sel8: создание GPU-ресурса

Вход 0x100 байт: `w[0]=0x82` (IOSurface), `w[0xe]=surfaceID`, `w[0xf]=plane`,
`w[0xc]=1`. Выход 0x1000:

```
q0  (+0x00) = 0x0000001500000000   GPU VA ресурса
q2  (+0x10) = user VA записи в shared-таблице
q5  (+0x28) = 0x4000              span
q6  (+0x30) = 0x000000036c468787  resource id
q10 (+0x50) = 0x4000              длина
```

`q2` — результат `IOGPUClientSharedMachine::getClientSharedAddressForId`:

```c
*out = map_base + stride * index;   // stride = 0xC0
```

Регион 0xC000 = 256 записей по 0xC0, замаплен в task **read-only** (`prot=0x1`).
Полный скан 0xC000 — **0 kernel-указателей**; содержимое: заголовок `0x4000`
и данные ресурса. Арена данных, не таблица указателей.

Чужие IOSurface ID 1..24 — **0 успехов**: lookup внутри IOGPU проверяет
владельца, как и `IOSurfaceRoot sel4` (в 2.4: found=0 на 1..0xfff).

### 2.5 Очереди

```
sel42 create io_command_queue -> 0x0, id=out[0] (малый namespace-id),
                                      out[1] = серийник объекта
sel43 destroy(id)             -> 0x0
sel46 create io command buffer-> 0x0, cbId=out[0]
sel47 release cb by id        -> 0x0
sel45 submit                  -> 0xe00002bc ВСЕГДА
```

Причина `0xbc` — в `FUN_fffffff00995b364`:

```c
if (*(u64*)(queue + 0x78) && *(u64*)(queue + 0x28)) { ...submit... }
return 0xe00002bc;
```

`queue+0x28` ставит только `sel44` (`FUN_fffffff00995b2ec`), и только один раз.
`sel44` требует объект из namespace `device+0x90` (`IOGPUNotificationQueue`),
которого из юзерспейса создать нечем: `sel44(q, 0..8)` → `0xe00002c2`.
**Сабит через IOCommandQueue недостижим.**

### 2.6 sel6 / sel25: командная очередь AGX

`FUN_fffffff0099476bc`:

```c
if (structureInputSize < 0x408 ||
    structureInputSize != *(u32*)(agx_object + 0x4f))
    return 0xe00002c2;
```

Перебор `0x408 … 0x8000` шагом 8 — **ни один размер не принят**. Причина:
обработчик IOGPU читает поле по смещению, которое у объекта AGX означает
другое. То есть IOGPU-таблица исполняется на объекте чужого класса.
`sel25` зависит от очереди из `sel6` → тоже недостижим.

**AGX как путь к записи закрыт структурно, а не «пока не угадали размер».**

## 3. AppleJPEGDriver

### 3.1 Настоящий ABI

```
AppleJPEGDriverUserClient, vtable 0xfffffff007e28d50
dispatch @ 0xfffffff007e293c0, stride 0x28 (IOExternalMethodDispatch2022)

sel0  in 0x0     out 0x0
sel1  in 0x58    out 0x58
sel2  in 0x0     out 0x0
sel3  in 0x58    out 0x58
sel4  in 0x1000  out 0x1000
sel5  in 0x1000  out 0x1000
sel6  in 0xda0   out 0xda0   descIn=1
sel7  in 0xda0   out 0xda0   descIn=1
sel8  in 0x4     out 0x0
sel9  in 0x0     out 0x0
```

Все 8 client types открываются.

### 3.2 Поведение

```
sel0 -> 0x0
sel2 -> 0x0
sel1/3/5/7 -> 0xe00002cc  (kIOReturnCannotLock)
sel4/6/8/9 -> 0xe00002bc  (kIOReturnError)
```

`0x2cc` одинаков для всех типов клиента, для свежего соединения, для всех
вариантов заполнения `0x58` (нули, `{ptr,len}`, `{len,ptr}`, размеры 64x64,
IOSurfaceID в 0x30/0x34/0x38, режимы `+0x2c` = 0..4).

### 3.3 Разбор sel1

Стаб `0xfffffff008c8fa94` → `0xfffffff008c85520`. Читает:

```
+0x00 u32, +0x04 u32
+0x08 u32, +0x0c u32
+0x14 u32 width
+0x18 u16 height
+0x20 u8  flags (bit0/1/2)
+0x24 u64
+0x2c u32 mode/format (ветвление 1..4)
+0x30 16 байт (копируются в объект запроса)
+0x40 u64
+0x48 u32
+0x4c u64
```

`0xe00002cc` в самом обработчике отсутствует — он приходит из vtable-метода
драйвера `+0xe8`, который вызывается после сборки запроса:

```asm
ldr x0, [x22, #0xb8]
ldr x16, [x0]
autda ...
ldr x9, [x16, #0xe8]!
blr x9
```

Метод требует **wired IOMemoryDescriptor**. У sel1/3/5 `descriptorCount = 0`,
то есть дескриптор не передаётся by design, а user VA и IOSurface ID драйвер
не принимает. **JPEG закрыт без настоящего memory descriptor-порта.**

## 5. Что нужно, чтобы двигаться дальше

Не селекторы и не размеры, а одно из двух:

1. **Баг памяти** в одном из достижимых драйверов (AGX / JPEG / Scaler):
   OOB-запись, UAF, type confusion. Признак — паника или corruption в
   crash-логе. За 21 прогон ни одного сигнала.
2. **Утечка адреса**: любой kernel-указатель в возвращаемой структуре.
   За 21 прогон ни одного.

Без этого произвольного kernel R/W на 27.2 из этих поверхностей не будет.
Достижимость и создание объектов — сделаны; эксплуатация не начата.
