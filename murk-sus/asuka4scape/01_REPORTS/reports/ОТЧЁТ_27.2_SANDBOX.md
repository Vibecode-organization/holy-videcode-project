## 1. App sandbox 27.2 — что реально можно

Профиль `container` (14 986 строк SBPL), наследует `baseline` (9 290 строк). Из `sb272/container.sb`:

* **mach-lookup**: 560 уникальных `global-name`; 463 — в одном безусловном блоке (строка 13159). Это и есть поверхность атаки приложения.
* **file-write**: прямых правил вне контейнера нет. Всё, что шире, закрыто `require-all` с `extension`/entitlement:
  - `com.apple.sandbox.container` — контейнер приложения;
  - `com.apple.classkit.read-write`, `com.apple.fileprovider.read-write` — узкие подкаталоги;
  - `com.apple.security.system-container` / `system-group` — системные контейнеры (у обычного app entitlement'а нет).
* **`iokit-open-user-client`**: `AppleMobileFileIntegrityUserClient` — только с `com.apple.private.amfi.can-load-cdhash`.
* **`process-exec`** в writable-пути: **нет ни в одном профиле** (проверено по всем 293).

## 2. Три двери

### 2.1. `installd` / install-time

`installd` (`_installd`) имеет:
`MobileContainerManager.allowed`, `security.storage.AppBundles`, `amfi.can-check-trust-cache`, `uninstall.deletion`.

Клиентский гейт — `com.apple.private.mobileinstall.allowedSPI` (`_ValidateMIAllowedSPIEntitlement`). Обычное app его не имеет; установку инициирует Apple-signed клиент (Xcode/App Store/Configurator) **или** пользователь ставит сам бандл.

Что смотреть в 27.2 `installd`/`MIBundle`/`InstalledContentLibrary`:
- `extractZipArchiveAtURL:toURL:withError:` — распаковка IPA;
- `_extractPackageContainedSymlink:withError:`, `_takeOwnershipOfInstallableContainingSymlink:error:`, `_installInstallable:containingSymlink:error:`;
- строки-маркеры: `Found symlink at destination path "%s"; this is not allowed.`, `realpath_parent_no_symlink`, `hardlink_copy_hierarchy`;
- `MIAppIdentity`/`MIBundle` — валидация `CFBundleIdentifier` и построение пути контейнера.

Сценарий: malicious bundle (TestFlight/enterprise/self-signed) при установке. Цель — symlink/identifier, который выводит запись за пределы `Payload/<App>.app` в `/private/var/containers/Bundle` или в чужой контейнер.

### 2.2. `containermanagerd`

`/usr/libexec/containermanagerd` (54 КБ) + `ContainerManagerCommon`/`ContainerManagerUser` (dsc).
Проверки в 27.2 framework:

```
Client [%@] is not entitled to look up container; identity = %@
Client [%@] is not entitled to look up unowned containers; containerClass = %llu
Client [%@] doesn't have permission to look up containers for at least one identifier in the query set.
Entitlement %@ value for %@ contains a slash [%@]; ignoring.
```

Клиентская identity строится из pid/audit token, entitlements — через `SecTask`. Искать: несоответствие между **query identifier** (bundle ID из запроса) и **client bundle ID**; обработку `MCMContainerClassBundle` vs `Data`; `checkAuthorization` (entitlement `com.apple.private.MobileContainerManager.checkAuthorization`).

### 2.3. `CoreTrust` / AMFI — arbitrary entitlements

Prior-находка: в `CoreTrust` 27.2 есть policy-ветка `FUN_94c2bd8` (`param_4 = 0` → `FUN_94c264c` → `FUN_94c82cc` с `param_4 ^ 1 = 1`), где **непиннутый корень принимается**. Вопрос — какой тип подписи/профиля идёт в эту ветку и можно ли провести туда self-signed цепочку. Если да — app подписывается с произвольными entitlements (`platform-application`, `com.apple.private.*`) → это и есть sandbox escape в модели TrollStore.

Что нужно для проверки:
- `amfid`, `libmis`, `installd` из 27.2 root FS (качается);
- профиль-цепочка leaf → intermediate (subject Apple CA) → self-signed root, CMS своим ключом;
- установка на устройстве (когда разблокируешь) и чтение `amfid`/`amfi` лога.

## 5. План после скачивания 27.2 root FS

1. Вытащить `094-*.dmg.aea` из IPSW, расшифровать `ipsw fw aea`, смонтировать/распаковать.
2. Достать `usr/libexec/installd`, `containermanagerd`, `amfid`, `sharingd`, `quicklookd`, `mediaparserd`, `streaming_zip_conduit`; `ldid -e` каждого.
3. Достать `InstalledContentLibrary.framework`, `MobileInstallation.framework`, `ContainerManagerCommon/User/System` из 27.2 dsc; аудит:
   - `extractZipArchive*`, `_copy_symlink`, `realpath_parent_no_symlink`, `hardlink_copy_hierarchy`;
   - `MIAppIdentity`/`MIBundle` identifier validation и container path;
   - `MCMClientIdentity`/`MCMEntitlementLookup`/`MCMCommandLookup`.
4. Проверить CoreTrust-ветку: собрать self-signed цепочку + CMS, поставить через `installd` с dev-профилем, прочитать `amfid` лог.
5. Когда разблокируешь телефон — прогнать статически найденный PoC и снять `amfi`/`sandbox` лог.

## 6. Честная граница

- Карта песочницы — **точная**: профили из ядра 24B115, не из 27.0.
- Бинари 27.2 ещё не на столе: IPSW качается. 27.0 baseline разобран, но 27.2 может отличаться.
- Рабочего escape нет. Найденные двери либо закрыты entitlement'ом, либо требуют аудита 27.2-бинаря, который появится после скачивания.
- Устройство locked; динамика (установка self-signed app, `containermanagerd` запросы) — после разблокировки.
