# Gap check — KASLR 24B115 (silvver, 2026-11-04)

Цель: проверить три «дыры» из отчёта id 1 и закрыть те, что не работают.

## Готово / закрыто

### IOSurfaceRootUserClient selector 0 (`0xfffffff009c3888c`) — ЗАКРЫТО как вектор утечки

Декомпиляция: `02_KERNEL/handlers_dump/fn_fffffff009c3888c.c`.

Что делает:
1. Проверяет, что верхние 32 бита `parentID` == 0.
2. Через `param_3+0x40` (IOBufferMemoryDescriptor) **мапит буфер клиента размером 0x1000**
   (`(**(code**)(*plVar3+0xe8))(plVar3, 0x1000)`).
3. Берёт VA (`+0x78`) и длину (`+0xb0`), вызывает `FUN_fffffff009c3ab8c(..., pcVar4, parentID, ..., len)`.

То есть направление данных — **user → kernel**: клиент даёт страницу, ядро её читает/парсит.
`FUN_fffffff009c3ab8c` в дампе отсутствует, но цепочка ниже (`0x9c38b2c` → `0x9c3c3b8` → `0x9c28220`)
— это десериализация содержимого страницы (`thunk_FUN_fffffff00a8d8754` / `0x894f30`), а не запись
указателей ядра обратно в user-память.

Вывод: как канал kernel→user это не работает. Оставляю только как «проверить на устройстве»
в общем скане, но приоритет снят.

### Границы, которые я физически не могу закрыть из MCP

- `exclaves_ctl` (mach trap 88, impl `0xfffffff00a21347c`) — функции нет ни в одном дампе
  (`handlers_dump/`), декомпилировать нечем.
- MIG `SubsystemStart(866900)` — routines безымянные, дампа нет.
- Запуск probe на iPhone — MCP не исполняет команды на хосте (README: shell/Ghidra/Frida не выполняет).

## Открыто, нужен прогон на устройстве

1. `exclaves_ctl` — проверить, доступен ли из sandboxed-приложения и что кладёт в `status`/буфер.
2. MIG 866900/866901/866902 — достать routine через userland-обёртку.
3. AGX/IOGPU shared memory — `IOConnectMapMemory64` + скан первой страницы.
4. IOSurface — доснять то, что не выполнилось из-за краша.

Инструмент: `scripts/kaslr_probe_v2.m`.
