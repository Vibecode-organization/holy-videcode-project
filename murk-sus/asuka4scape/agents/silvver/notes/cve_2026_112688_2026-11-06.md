# CVE-2026-112688 внешний PoC — заметка (2026-11-06)

Источник: https://github.com/0xjohnnydev/CVE-2026-112688-backboardd
Отчёт: id 25 (`логи работы ИИ/2026-11-06/221825_...`).

## Что проверено и чем

1. **CVE реален.** support.apple.com/en-us/149230 (iOS 27.2, 26 окт 2026):
   CoreMedia, «Parsing a file may lead to an unexpected app termination or
   arbitrary code execution», «memory corruption … improved memory handling»,
   CVE-2026-112688: 정우 하 (@0xfa11babe), Chris Bailey - Short Circuit.
   README цитирует дословно.

2. **Crash-лог подлинный по байтам кода.**
   `evidence/return-address/backboardd-2026-10-28-113235.ips`:
   - atPC[0:4] = `df 91 20 55` = инструкция `retabsppc` по PC 0x19bdec6c4;
   - atPC[4:8] = `68 62 31 b0` = `adrp x8, 0x1e7199000`;
   - beforePC = `aa1303e0 910e03ff a9477bfd …` = эпилог 0x18454c688..0x18454c6c4;
   всё совпадает с `evidence/disassembly/quartzcore-frame.dis` байт-в-байт.

3. **Арифметика сходится:**
   ```
   0x19bdec6c4 - 0x2026c4   = 0x18434A000      # unslid base QuartzCore
   0x18434A000 + 0x5FD07088 = 0x1E4051088      # unslid __bss-цель (.dis)
   0x19bbea000 + 0x5FD07088 = 0x1FB8EB088      # то же, Slid (FixedByteRPU)
   ```

4. **ГРАБЛИ:** `exception.codes[1]` = `0x552091df` и vmRegionInfo «not in any
   region» — это НЕ указатель, а little-endian кодировка `retabsppc`.
   Не трактовать как FAR.

## Слабые места

- zero-control снят на другом экземпляре backboardd (pid 725 vs 794) — переход
  0→1 в одном процессе не показан (автор это сам признаёт);
- readback — косвенный краш-оракул (`IOSurfaceSetBulkAttachments2 ←
  iosurface_set_edr_factor`), без дампа памяти/kdump;
- 1 коммит, 1 автор, «sanitized operator summary», нет sysdiagnose/билдера RPU;
- build `24A94425` не похож на нумерацию нашего архива (27.0.1=24A446,
  27.2=24B115); в README «iPhone Duo», в логе `iPhone19,4`.

## Роль в наших задачах

- kernel R/W **не даёт** — это userland → userland-демон.
- Полезно как: вторая поверхность CoreMedia (Dolby Vision RPU, доставка из
  обычного приложения) + пример «OOB в стек парсера → saved LR → PAC».

## Что делать дальше

1. Спросить автора: same-PID zero control + сырые логи + билдер RPU.
2. Запросить у admin IPSW/kernelcache 27.1 (24A9…) — без него адреса не сверить.
3. Из нашего 27.2 DSC (24B115) вытащить CoreMedia, найти аналог 0x18ec67544,
   проверить, появился ли `cmp`/`b.hs` перед индексом — это и есть fix shape.
