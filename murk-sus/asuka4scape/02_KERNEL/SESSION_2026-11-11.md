# Session 2026-11-11 — MCM escape + IOGPU IOCommandQueue (27.2/24B115)

## Итог

- **MCM class-7 symlink escape подтверждён на живом устройстве.**
  - `consume=3..56`, путь `/private/var/mobile/Containers/Shared/AppGroup/4F933082-.../Library/Caches`.
  - `MG loaded: 80 CacheExtra key(s), 10776 byte(s)` — прочитан системный MobileGestalt cache.
  - Найден контейнер PosterBoard `/var/mobile/Containers/Data/Application/967AA218-...`.
- **Шрифт:** `fonttest user scope=0 code=307`, `process scope=1`, `family=Minecraft Rus`. Системная установка не подтверждена.
- **Новый kernel primitive: user-controlled command list в `IOGPUIOCommandBuffer::processKernelCommands`.**
  - `sel14` — notification queue: возвращает `{u64 user_va, u32 id}`.
  - `sel12` — `s_create_shmem`: `{u64 user_va, u32 len, u32 id}`; shmem добавлен в namespace `device+0x78`, user-mapped RW.
  - `sel42` — create IO command queue: type 0/1 valid, priority 0; `{qid, serial}`.
  - `sel44` — bind notification queue.
  - `sel46` — create IO command buffer: `{cb_id, serial}`.
  - `sel45` — submit; entry 0x18 bytes: `{u32 shmem_id; u32 cb_id; u64 addr; u32 flags; u32 pad}`, header `{u32 count; u32 pad}`.
  - Kernel log подтверждает, что парсер читает **наш** shmem:
    `IOGPUIOCommandBuffer::processKernelCommands: Invalid command list header, commands_start=0 commands_end=1073741824 cmdListShmemLength=16384`
  - `sel45/46/49/50` return 0; parser reachable.
- **Блокер:** command type 0 (`sIOGPUIOKernelArgs`, body 0x30) с любым `id`/полями, кроме пустого заголовка, убивает GPU-клиент (DART/GPU fault). Barrier type 1 с user VA / GPU VA / kernel VA также убивает клиент. Completion address — транслированный DVA, не user/GPU/kernel VA.
- **Не получено:** kernel read/write, KASLR leak, SPTM bypass, CoreTrust bypass. Публичного jailbreak для 27.2 нет; SPTM bypass, закрытый в 27.2 beta 3, отсутствует.

## Ключевые адреса/функции (kernelcache 27.2)

- `FUN_99959e20` — обработка дескрипторов; type 1 barrier completion address — 64-bit.

## AGX sel6+sel8+sel25 (после 01:20)

- Отдельный bundle ID `app.lake9674.aquila8809.agx` **устанавливается с тем же профилем**; общий `app.lake9674.aquila8809` и приложения других агентов не трогаются.
- `sel6` (AGXCommandQueue) создаётся с `structureInput 0x410`, `+0x404=1`; возвращает `{qid, serial}`.
- `sel8` IOSurface (type 0x82): `q0=GPU VA 0x1500000000`, `q4=0x100000000` → **resource id = 1** (`out+0x24`), `q6` — серийник, `q7` — namespace key.
- `sel8` sysmemory (type 0x80): `q0=0x150000c000`, id=2.
- `sel12` type 2 (AGXDebugBufferShmem): `addr=user VA`, `len=0x4000`, `id=1`.
- `sel25` с `record+0x20` = id/0 и `record+0x18` = GPU VA (0x1500000000/0x150000c000) **всегда возвращает `0xe00002bc`**.
- `FUN_997700c`: `0xbc` = firmware command-buffer factory `accel->vt[0x5c0]` / init `vt+0x90` не создаётся (status 8). Это блокер AGX submit: нужен старт firmware-объекта очереди (`q+0x610`, слот 43) или валидный init.
- IO command queue (sel42/44/46/45) работает: парсер читает наш sel12 shmem (`cmdListShmemLength=16384`), но type 0/1 completion address — DVA; user/GPU/kernel VA дают GPU fault и убивают клиент.

## TTBAT / resType 0x40 (15:10–15:18)

- SPTM 27.2 (820.40.24) TTBAT-скип **жив**: `MAP_BEGIN` не вызывает `FUN_270e1168`, если `out_pa == uat_instance[0x68]`; `gpu-region-base` = **0x04D00000**, размер 0x20000 (8×16K).
- `sel8 resType=0x40` с `+0x38 = 0x04D00000`, `+0x40 = 0x4000`, `+0x50 = 0x4000` **принимается**:
  - `q0 = 0x1500000000` (GPU VA), `q10 = 0x4d04000` (end), `q3 = 0x100abc000` (user VA).
  - `q3` — **RW, 0x4000, prot=3**, но содержимое **все нули**: это свежая zero-page/metadata, **не** физическая страница TTBAT.
- `addr = kernel VA` (`0xfffffff007004000`, `0xfffffff00af00000`) → `0xe00002be` (invalid).
- `addr = 0x100000000` тоже принимается, q3 — zero-page.
- Вывод: `resType 0x40` трактует `+0x38` как **GPU VA**, а не PA; paddr-контроля нет. TTBAT PA 0x04D00000 в user/GPU-контекст не мапится.
- `sel1`/`sel2`/`sel4` не дают IOUAT/kernel pointer: sel1 = "AGXG14P", sel2/sel4 pages — конфиг/нули; KASLR-формула silvver на 24B115 не подтвердилась.
- Публичного kernel R/W для 27.2/A15 нет; SPTM bypass 27.2 beta 3 закрыт; usbliter8 — только A12/A13.
