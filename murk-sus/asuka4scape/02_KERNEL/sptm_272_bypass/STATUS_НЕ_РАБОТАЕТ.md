# СТАТУС: полный SPTM-байпас 27.2 RC НЕ РАБОТАЕТ

Дата: 2026-11-02
Цель: iOS 27.2 RC, билд 24B115, iPhone14,7 (T8110) — снять контроль SPTM.

## Что не работает

Полный байпас не собран. Нет рабочей цепочки «userland → снятие SPTM».
Причина одна и конкретная: отсутствует звено, дающее **произвольный paddr**
на входе UAT MAP_BEGIN. Без него скип проверки для `gpu-region-base` не вызвать.

## Что проверено и работает (это не догадки)

1. `FUN_0xfffffff0270adf30` в SPTM 27.2 — UAT MAP_BEGIN. Для страницы с
   `paddr == uat_instance[0x68]` (gpu-region-base, TTBAT) вызов проверки прав
   `FUN_0xfffffff0270e1168` **пропускается**; для table-типов
   {2,3,5,6,7,9,10} — паника.
2. `FUN_0xfffffff0270e1168` проверяет FTE-тип и max permissions по текущему
   dispatch id; таблицы `0x27092228` / `0x27092230`.
3. `FUN_0xfffffff0270abc74` при release контекста проверяет валидность записей
   TTBAT (`{paddr, flags}`) и паникует `TTBAT already contains invalid entries`.
4. В 27.2 есть violation-имена `VIOLATION_UAT_ILLEGAL_TTBAT_MAPPING` и
   `VIOLATION_UAT_ILLEGAL_TTBAT_LOCK` — класс атаки известен Apple.
5. SPTM 27.2 (820.40.24) sha256
   `a29fbc4f54c10888e25372a47410669b9857787adbee4feac3af37f15701d083`.

  kernel-баг с контролем paddr, а не чтение одной функции. В 27.2 известные
  userland-поверхности для этого закрыты (отчёты 27.2-ФИНАЛ, KASLR/CoreTrust).

## Что нужно, чтобы файл стал «работает»

1. Ghidra-проект или импорт **24B115/T8110** ядра.
2. Перечислить call-site UAT MAP_BEGIN в ядре и найти источник paddr.

4. Собрать [2]–[5]: PTE на TTBAT → своя таблица → GPU DMA → kernel R/W.

## Дополнение, второй заход (2026-11-02)

Проверена гипотеза PA-контроля через `IOSurfaceAddress` на 24B115.
**Закрыта кодом.** Для пользовательского клиента `surface+0x170 = owningTask != 0`,
поэтому адрес трактуется как virtual64, а не physical64. Физическая ветка
(`IOMemoryDescriptor::withAddressRange(..., task=NULL)`) доступна только
kernel-клиентам.

Точные адреса и цепочка аргументов — в `ОТЧЁТ.md`, раздел «Дополнение».

Что это значит: звено [1] (произвольный paddr в UAT MAP_BEGIN) по-прежнему
не найдено. SPTM-примитив (скип проверки для `gpu-region-base`) подтверждён,
но без paddr-контроля он не срабатывает.
