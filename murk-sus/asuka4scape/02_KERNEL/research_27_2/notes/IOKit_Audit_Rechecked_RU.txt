  4. Перепроверка IOAccessoryManager
  До: fffffff00a177e4c
  После: fffffff0098d9b70

  Соответствие пары остаётся эвристическим: она найдена по упорядоченному блоку функций. В каждой
  функции индекс проверяется до чтения 32-битного элемента таблицы; вне диапазона возвращается 0.

    До:    if ((uint)(value - 1) < 6)
             return old_table[value - 1];
    После: if ((uint)(value - 2) < 4)
             return new_table[value - 2];
    Обе:   return 0;


    Сторона      Адрес таблицы / file offset                       Прочитанные значения

    До           fffffff0077485c8 / 0x7445c8                       0, 50, 50, 500, 500, 0

    После        fffffff00778b610 / 0x787610                       50, 50, 500, 500


  Независимое чтение исходных байтов подтвердило обе таблицы. Для показанных функций и этих
  фиксированных значений результат совпадает для всех 32-битных входов: 2 и 3 дают 50; 4 и 5 дают 500;
  остальные дают 0. Старые крайние нули заменены возвратом нуля через ветвь вне диапазона.

  Вывод: изменение согласуется с оптимизацией таблицы. Оно не подтверждает исправление
  произвольной записи. В показанном фрагменте нет записи в выходной буфер и нет установленного
  IOMemoryDescriptor.

  Что пришлось уточнить в прежних ответах
  14 успешных этапов означают успешное исполнение скриптов, а не чистый аудит безопасности.
  Последний запуск использовал 88 395 готовых файлов C-подобного вывода; заново проверялись две
  ошибки декомпиляции. Различия псевдокода включают перенос адресов и артефакты восстановления
  типов, а не только изменения логики.

  6. Проверки, ограничения и материалы
  Независимая проверка согласованности
  Проверены все записи ассемблера: повторный SHA-256 байтов инструкций и число инструкций
  совпадают с инвентаризацией. Исходные байты из обеих баз соответствуют сохранённым SHA-256.
  Пары уникальны между компонентами; списки пар и несопоставленных функций покрывают выбранные
  входные наборы. Количество секций в .diff совпадает с числом диффов. Ошибок этих проверок нет.

  Две ошибки Ghidra
    До:    fffffff00a0d9cbc
    После: fffffff00984ac78
    Low-level Error: Cannot properly adjust input varnodes

  Для обеих функций сохранён ассемблер. Неуспешная декомпиляция - ограничение инструмента, а не
  установленная ошибка исследуемой функции.

  Границы выводов
  IOKit внутри com.apple.kernel и код com.apple.driver.* этим префиксным проходом не охвачены. Поэтому
  отчёт нельзя называть полным аудитом всего IOKit. Несопоставленные функции не равны новым,
  удалённым или исправленным функциям.

  Это вывод Ghidra, не исходники Apple. Типы undefined, имена param_* и локальные имена не
  доказывают исходный прототип или layout. Достижимость из приложения, права, полные пути обработки
  буферов и время жизни объектов не доказаны. Динамические тесты не выполнялись. Происхождение и
  подпись IPSW независимо не проверены.
