1. Резюме (Executive Summary)
Настоящий документ представляет сравнительный анализ двух сборок кекста com.apple.iokit.IOSurface,
входящих в состав ядер iOS версий 26.6.1 (сборка N2) и 26.6 (сборка N3). Источниками данных послужили
листинги Ghidra, предоставленные в виде текстовых файлов IOSurfaceN2.txt (6 857 059 байт) и
IOSurfaceN3.txt (6 025 281 байт). Целью анализа является выявление архитектурных и поведенческих
изменений между двумя минорными версиями iOS, оценка их влияния на attack surface и формирование
рекомендаций для дальнейшего реверс-инжиниринга.

Сравнение показало, что N2 является строгим расширением N3: ни одна строка или секция не была
удалена полностью, все изменения носят аддитивный характер. Совокупный объём исполняемого кода
(__TEXT_EXEC.__text) вырос на 17 144 байта (+8,9%), объём строковых констант — на 1 069 байт (+8,9%).
Число уникальных функций выросло на 111 (с 1 389 до 1 500), число ссылок XREF — на 1 011 (+13,2%).
Эти показатели согласованно указывают на внедрение новой подсистемы объёмом порядка 17 КБ кода и
порядка 100 новых функций.

Главное архитектурное нововведение — подсистема IOSurfaceAgentMask: новый класс
IOSurfaceAgentMaskInfo      с   12    полями     и    5   методами     (handleAgentMaskRegistration,
assignAgentMaskSlot,                addAgentMaskForSignalValue,                  copyAgentMaskMemory,
assignSlotAndCopyAgentMaskMemoryForSignalValue). Все семь идентифицирующих AgentMask-строк
присутствуют в N2 и полностью отсутствуют в N3. Подсистема реализует механизм «агентских масок» с
ограниченным пулом слотов, привязанных к signal values shared event, что является принципиально новой
точкой входа для пользовательского пространства через IOSurfaceRootUserClient.

Дополнительно в N2 появились: новый класс IOSurfaceMemoryCallback (callback для асинхронных
операций memory pool), тип IOSurfaceSmaMemoryRegion, метаданные ScalableMemory, GPU hint
AGXUseNearestChromaFiltering, подсистема runtime-tunable конфигурации (16 отладочных флагов,
включая PanicOnAgentMaskSlotExhaustion) и 5 новых external-методов memory pool API
(ensure_memory_pool_memory, flush_memory_pool, gather_memory_pool_data, append_transaction,
newMemoryPool). Изменена ABI четырёх классов (IOSurfaceSharedEventListener, IOSurfaceSharedEvent,
IOSurfaceShared, IOSurfaceRootUserClient) — добавлены новые поля, что делает несовместимыми с N2
любые существующие эксплойты, рассчитанные на конкретные смещения.


   Общая оценка риска: MEDIUM. Новая attack surface (5+ user-facing external methods, AgentMask slot
   exhaustion, callback API) создаёт вектор для privilege escalation и DoS. Уровень детализации в разделах
   5–9 позволяет prioritizировать цели для дальнейшего реверс-инжиниринга.


2. Источники и методология
2.1. Файлы-источники
Анализ выполнен на основе двух Ghidra-листингов (plain text dumps), предоставленных пользователем.
Файлы не являются оригинальными Mach-O бинарями — это текстовые представления
дизассемблированного кода с метаданными секций и кросс-ссылками XREF. Идентификация сборки iOS
выполнена по содержимому __TEXT.__cstring: сигнатуры bundle ID, имена классов и формат
error-сообщений согласуются с публично известными kext-билдами iOS 26.6.x.

2.2. Методология
Сравнение выполнено в три прохода. Первый проход — структурный разбор Mach-O через парсинг
секционных заголовков листинга в формате // __section / __segment / ram:start-ram:end. Для каждой секции
вычислен размер в байтах как разность конечного и начального адресов плюс один. Второй проход —
статистический подсчёт уникальных символов FUN_* и DAT_* (через grep -oE | sort -u | wc -l) и
общего числа XREF-ссылок (через grep -cE 'XREF\['). Третий проход — побайтовое сравнение
строковых литералов секции __TEXT.__cstring: для каждого листинга извлечены все ds "…"-литералы,
построены множества уникальных строк и вычислены разности (только в N2, только в N3, общие).

Глубокий     анализ    функции       assignSlotAndCopyAgentMaskMemoryForSignalValue и   других
AgentMask-методов выполнен вручную: по именам функций, привязанным к XREF-ссылкам из строковых
литералов, восстановлены callgraph-связи и оценено их назначение.

2.3. Ограничения метода
Ghidra-листинги не содержат имён импортируемых функций (символы LC_SYMTAB исключены из
дизассемблированного вывода); идентификация внешних вызовов выполнена только по строковым
подсказкам. Адреса FUN_* и DAT_* в N2 и N3 различаются из-за KASLR-relocation (сдвиг составил
0x100B0E0 между сборками), что исключает побайтовое сравнение конкретных инструкций. Сравнение
проведено на уровне строк, секций и статистических показателей; для углублённого анализа конкретных
функций требуется оригинальный Mach-O бинарь, декодированный LinkEdit, или интерактивный
Ghidra/IDA project с символами.

дизассемблера.

4.1. Анализ дельт секций
Наибольший прирост в абсолютном выражении наблюдается у секции __TEXT_EXEC.__text (+17 144 байт,
+8,9%) — это новый исполняемый код подсистем AgentMask и memory pool API. Секция
__DATA_CONST.__const выросла на +1 016 байт (+5,9%): здесь размещены новые vtable и type descriptors для
четырёх изменённых классов. Секции __TEXT.__os_log (+1 235, +10,0%) и __TEXT.__cstring (+1 069,
+8,9%) содержат новые panic/error-сообщения и форматные строки для подсистемы AgentMask.

Появилась новая секция __TEXT_EXEC.__auth_stubs объёмом 2 304 байта (в N3 отсутствовала). При
стандартном размере PAC-stub в 32 байта на ARM64e это соответствует 72 новым cross-kext вызовам,
импортирующим функции из kernel, PPL или других кекстов. Это согласуется с добавлением 5 новых
external-методов IOSurfaceRootUserClient и подтверждает, что Apple вынесла PAC-стабы из inline-кода в
отдельную секцию для улучшения icache-locality.

Секции __DATA_CONST.__kalloc_type (+320, +10,6%) и __DATA_CONST.__kalloc_var (+320, +13,3%)
выросли за счёт добавления type descriptors для четырёх новых классов (IOSurfaceAgentMaskInfo,
IOSurfaceMemoryCallback, IOSurfaceSmaMemoryRegion, IOSurfaceMemoryRegionNode) и одной новой
переменной kalloc-var. Секции __mod_init_func и __mod_term_func выросли на +16 байт (+12,5%) —
добавлено по одной функции инициализации и финализации (по 16 байт на указатель). Секция
__DATA.__common выросла на +80 байт (+7,7%) — это глобальные статические переменные новой
подсистемы AgentMask (массив слотов, lock, статистика).

Данное переупорядочивание является косметическим изменением компоновки Mach-O, не влияющим на
функциональность: Apple переставила секции так, что растущие при добавлении новых классов блоки
__kalloc_type и __kalloc_var оказались перед __auth_got, что упрощает динамическое расширение этих
секций без сдвига GOT. Появление новой секции __TEXT_EXEC.__auth_stubs (2 304 байта, отсутствует в
N3) согласуется с общей тенденцией Apple по вынесению PAC-stub в отдельную секцию для улучшения
locality icache.

Подсистема AgentMask добавила 9 новых диагностических сообщений в секции __TEXT.__os_log и

  %s: failed to assign agent mask slot for value %llu
  %s: failed to add agent mask for value %llu: ...
  %s: No free agent mask slots available for event %08x
  Currently allocated slots:
  Slot[%u]: SignalValue=0x%016llx Timestamp...
  %s: slot index %u out of range or no agent mask...
  %s: slot index %u validation failed: allocate...
  %s: slot index %u is out of range for event %08x
  %s: slot index %u is not allocated for signal %llu
  %s: failed to assign slot for event %08x, sig...

                 Листинг 7.1. Диагностические сообщения AgentMask (адреса в N2 — см. приложение).

Шаблоны сообщений указывают на трёхуровневую валидацию: (1) общая проверка slot index попадания в
диапазон массива слотов; (2) проверка что слот действительно аллоцирован для конкретного signal value; (3)
проверка signal value на валидность перед копированием памяти маски. Появление
PanicOnAgentMaskSlotExhaustion как runtime-tunable флага указывает, что поведение при исчерпании пула
слотов может переключаться между panic (безопасный режим) и silent failure (диагностический режим). Это
создаёт потенциальный вектор DoS-атаки, если attacker может контролировать установку флага в 0.

Внимательный анализ показал, что все 54 строки «только в N3» являются не удалёнными строками, а
предыдущими версиями N2-строк без суффикса \n. Apple добавила перенос строки в конце ~50
диагностических сообщений для консистентности формата вывода. Поскольку сравнение выполнено на
уровне точного строкового соответствия, такие модифицированные строки попали в обе категории: новая

10. Ограничения и рекомендации
10.1. Ограничения анализа
Сравнение выполнено на уровне текстовых Ghidra-листингов, что накладывает ряд принципиальных
ограничений. Во-первых, листинги не содержат имён импортируемых функций — символы LC_SYMTAB
исключены из дизассемблированного вывода, поэтому идентификация внешних вызовов выполнена только
косвенно, по строковым подсказкам и именам методов. Во-вторых, адреса всех символов FUN_* и DAT_* в
N2 и N3 различаются из-за KASLR-relocation, что исключает прямое побайтовое сравнение инструкций или
выполнение инструкционного diff. В-третьих, настоящий отчёт не включает декомпилированный псевдокод
(C-представление) — для каждой функции нужен отдельный Ghidra/IDA project.

Дополнительно, настоящее сравнение охватывает только кекст IOSurface. Корреляция с другими кекстами
(CoreTrust, SPTM, IOSurfaceBroker) проведена на уровне строковых совпадений, но не на уровне callgraph
— это отдельная задача.

10.2. Рекомендации для дальнейшего анализа
R1. Статическое извлечение кекста из IPSW.
Получить оригинальный Mach-O бинарий com.apple.iokit.IOSurface из IPSW iOS 26.6.1 и iOS 26.6,
декодировать LinkEdit и извлечь имена импортируемых функций через LC_SYMTAB. Это позволит точно
идентифицировать все 72 новых cross-kext stubs.

R2. Интерактивный Ghidra/IDA project.
Загрузить оба бинария в общий Ghidra project с применёнными symbol-tables. Выполнить декомпиляцию 5
ключевых функций AgentMask (FUN_a01dda4, FUN_a01ded8, FUN_a01e104, FUN_a03c5d8, FUN_a03c75c)
и 5 функций memory pool API (FUN_a043c80, FUN_a043f78, FUN_a044270, FUN_a045e90, FUN_a048e00).
Цель — подтвердить гипотезы о race condition в FUN_a03c75c и privilege escalation в
copyObjectForPortNameInTask.

R3. Cross-kent корреляция.
Сопоставить findinings настоящего отчёта с отчётами по CoreTrust (CoreTrust1_vs_CoreTrust2) и SPTM
(SPTM2_vs_SPTM3). Гипотеза: все три кекста обновлялись синхронно под одну security feature iOS 26.6.1
(вероятно — расширенная проверка trust anchors и manifests для новых типов kext-extensions).

R4. Анализ KASLR-relocation.
Выполнить нормализацию адресов N2 к N3 путём вычитания сдвига 0x100B0E0. После нормализации
можно построить адрес-маппинг FUN_* между сборками и выполнить инструкционный diff для функций,
которые не были изменены (control-group).

R5. Runtime verifikation.
На jailbroken-устройстве iOS 26.6.1 проверить наличие 16 отладочных флагов через переменные boot-args
или NVRAM. Цель — определить, можно ли извне установить PanicOnAgentMaskSlotExhaustion=0 и
AllGlobal=1 (security bypass).

11.2. Глоссарий
Mach-O. Формат исполняемых файлов macOS/iOS. Состоит из сегментов (__TEXT, __DATA,
__DATA_CONST, __TEXT_EXEC, __LINKEDIT), каждый из которых содержит секции.

KASLR. Kernel Address Space Layout Randomization. Случайное смещение адресов загрузки ядра и кекстов
при каждой загрузке, защита от ROP-эксплойтов.

PAC. Pointer Authentication Codes (ARM64e). Криптографическая подпись указателей, предотвращающая
подмену адресов возврата и vtable.

GOT / __auth_got. Global Offset Table. Таблица указателей на импортируемые функции. __auth_got —
PAC-authenticated версия.

__auth_stubs. Секция коротких стабов, выполняющих PAC-аутентификацию и переход по адресу из
__auth_got. Apple выносит их в отдельную секцию для icache locality.

XREF. Cross-reference в Ghidra. Каждая XREF — указание на то, что данный символ используется в другой
точке кода. Число XREF — мера связности.

AgentMask. Новая подсистема iOS 26.6.1 в кекте IOSurface: механизм «агентских масок» с ограниченным
пулом слотов, привязанных к signal values shared event.

kalloc type descriptor. Метаданные о структуре класса для kernel allocator. Содержит сигнатуру полей
(например, 12222222222221 = 1B + 11×qword + 1B).

LC_SYMTAB. Load command в Mach-O, описывающая таблицу символов. В Ghidra-листингах обычно не
экспортируется.

ABI. Application Binary Interface. Контракт на уровне бинарного представления структур и вызовов
функций. Изменение layout класса — ABI breaking.
